# Technical Architecture

## System Layers

```text
Agent Layer
    ↓
Planning / IR Layer
    ↓
Plugin & Capability Layer
    ↓
Compiler / Runtime Layer
    ↓
Render Adapter
    ↓
Remotion
```

## 1. Agent Layer

Claude Code and Codex are external coding agents.

Responsibilities:
- understand user intent
- inspect project context
- choose scene intent
- search available capabilities
- generate or patch storyboard data
- respond to validation failures

The agent should avoid arbitrary React/Remotion implementation unless explicitly operating in developer mode.

## 2. Storyboard / Motion IR

The storyboard is the contract between agents and the runtime.

It should describe:
- metadata
- scenes
- semantic intent
- elements
- actions
- timeline relationships
- layout requests
- theme/plugin preferences

It should not contain:
- raw CSS
- arbitrary React code
- low-level Remotion frame calculations
- hard-coded pixel positions unless explicitly supported

## 3. Plugin Registry

The registry contains installed capabilities.

Examples:

```text
diagram.node.service
diagram.node.database
diagram.connection.request
ui.loading
ui.progress
scene.architecture
scene.product-demo
motion.highlight
```

Multiple plugins may provide the same capability.

The resolver decides which implementation is valid for the current context.

## 4. Semantic Resolver

Input:
- requested capability
- scene type
- semantic intent
- theme
- project preferences
- plugin constraints

Output:
- eligible implementations
- selected implementation
- resolution diagnostics

The first implementation should use deterministic rules and scoring, not embeddings.

## 5. Validation

Validation should happen in stages.

### Schema validation
Checks shape and types.

### Referential validation
Checks that referenced nodes, events, scenes, and IDs exist.

### Semantic validation
Checks compatibility rules.

### Runtime validation
Checks whether all requested capabilities can be resolved.

## 6. Timeline Compiler

Converts semantic and dependency-based timing into frame ranges.

Example:

```text
api-enter
    ↓
redis-enter
    ↓
connection-draw
    ↓
redis-activate
```

The compiler should:
- resolve `after` dependencies
- detect cycles
- produce deterministic frame ranges

## 7. Layout Compiler

Transforms semantic layout requests into concrete positions.

Example inputs:
- center
- split
- horizontal-flow
- grid
- graph LR
- graph TB

Pixel-level layout should be generated by the layout system, not normally by the agent.

## 8. Render Plan

Core output before Remotion.

```ts
type RenderPlan = {
  scenes: CompiledScene[];
  durationInFrames: number;
  fps: number;
  width: number;
  height: number;
};
```

The Motion Core should compile to `RenderPlan`.

## 9. Remotion Adapter

The Remotion adapter translates `RenderPlan` into React/Remotion compositions.

Core should not directly depend on Remotion-specific primitives such as `<Sequence>`.

## Architectural Boundaries

### Core may know
- storyboard
- capabilities
- plugin metadata
- semantic rules
- timeline
- layout abstractions
- render plan

### Core should not know
- desktop UI state
- marketplace APIs
- Tauri commands
- Claude/Codex internals
- direct Remotion UI components

### Desktop may know
- project files
- preview
- inspector state
- render queue
- plugin manager UI
- agent interaction

### Desktop should not duplicate
- validation
- capability resolution
- timeline compilation
- render planning
